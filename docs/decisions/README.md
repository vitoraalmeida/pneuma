# Architectural Decisions

An architectural decision record (ADR) explains why Pneuma chose a significant
architecture. Create one when reversing the choice would substantially change
the platform's architecture or operating model.

ADRs are concise and use this format:

```text
# ADR-NNNN - Title

Status: Accepted

## Context
## Decision
## Alternatives Considered
## Consequences
## References
```

Architecture documents describe what works today. ADRs explain why a major
choice was made. Design documents explain how an approved future capability will
work.

The initial ADRs are retrospective: they document decisions already embodied in
the implementation. They do not claim that every alternative was formally
evaluated when the original code was written. Accepted ADRs are historical
records; superseding decisions receive a new ADR rather than rewriting an old
one.
